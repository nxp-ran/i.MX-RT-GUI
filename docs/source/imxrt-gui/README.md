## 一、这个系列要解决什么问题？

做嵌入式 GUI，最容易遇到的情况是：屏幕已经点亮，示例也能运行，但换一块屏幕、提高分辨率或加入动画后，问题就接踵而来。

- SPI、8080、RGB、MIPI DSI 屏幕应该怎么选？
- 显示控制器、DMA、PXP 和 GPU 分别负责什么？
- 为什么 CPU 主频很高，界面还是不流畅？
- 双缓冲为什么仍然可能撕裂？
- 为什么打开 Cache 后性能提高了，却偶尔出现旧画面？
- LVGL 的硬件加速到底有没有真正生效？

本系列不把这些问题拆成互不关联的技巧，而是沿着一条完整的数据路径展开：

```text
应用逻辑与用户交互
        |
        v
LVGL：控件、布局、事件、无效区域与绘制任务
        |
        v
CPU 软件绘制 / PXP / GPU：按任务与平台能力选择
        |
        v
像素缓冲区：绘制缓冲区、显示帧缓冲区
        |
        v
显示控制器 / 传输外设
        |
        v
屏幕控制器 / 面板
```

这是一张逻辑关系图，不是所有芯片都采用的固定硬件拓扑。存储系统、总线带宽、Cache 一致性和同步机制贯穿其中。

读完这个系列，希望读者不仅能“把例程跑起来”，还能解释像素从哪里来、经过哪些模块，以及系统瓶颈在哪里。

## 二、范围与写作约定

### 2.1 面向哪些读者？

- 准备使用 i.MX RT 开发带屏产品的嵌入式工程师。
- 已经点亮屏幕，希望理解显示原理和性能边界的开发者。
- 正在移植 LVGL，或准备引入 PXP / GPU 加速的工程师。

建议具备 C 语言、MCU 外设、中断和基础 RTOS 知识。不要求提前掌握图形学。

### 2.2 平台范围

以四位数型号的 i.MX RT 为讨论范围，涉及具体功能时，始终落实到明确的芯片型号、封装、开发板和 SDK。

需要坚持以下边界：

1. **不根据系列名称推断功能。** 不是所有型号都具备相同的显示接口、PXP、GPU 或外部存储接口。
2. **区分四层支持。** 芯片具备硬件、开发板引出接口、SDK 提供驱动、LVGL 具备适配，是四件不同的事。
3. **区分显示与绘制。** 显示控制器负责输出像素；PXP / GPU 负责其支持范围内的像素处理或图形绘制。
4. **区分硬件与软件。** VG-Lite 是图形软件 API / 驱动栈，不是与 PXP、GPU 并列的硬件外设。
5. **固定软件版本。** 涉及具体代码时明确 SDK 和 LVGL 版本，不混用不同 LVGL 主版本的接口。
6. **区分理论与实测。** 计算值写清假设；性能结果必须附带测试平台、场景和测量方法。

主讲开发板、屏幕和软件版本应在进入平台相关实战前确定。本总纲不预设某块开发板拥有全部图形能力。

## 第五部分：从零移植到理解 LVGL

### 第 17 篇：LVGL 最小移植——让软件绘制先跑起来

**核心问题：** 怎样建立一个不依赖硬件加速、行为正确的 LVGL 基线？

**主要内容：**

- 固定开发板、屏幕、SDK 和 LVGL 主版本。
- 接入时间基准、任务处理和显示驱动。
- 配置绘制缓冲区和目标像素格式。

## 四、贯穿全系列的实验主线

### 4.1 固定场景，逐步增加复杂度

| 阶段 | 场景 | 主要观察点 |
| --- | --- | --- |
| 1 | 纯色与色条 | 接线、时序、像素格式 |
| 2 | 图片显示与搬运 | 存储位置、传输效率、DMA |
| 3 | 局部区域更新 | 无效区域、地址窗口、局部刷新收益 |
| 4 | 透明图层混合 | 像素读写量、PXP / GPU 适用性 |
| 5 | 缩放与旋转 | 后端能力、质量、对齐和吞吐 |
| 6 | 动态仪表盘 | 综合帧率、输入延迟、CPU 与内存压力 |

不是每个平台都必须执行所有硬件路径。缺少的能力应明确标记，不使用不可比的工作负载代替。

### 4.2 固定测试记录格式

| 分类 | 至少需要记录的内容 |
| --- | --- |
| 硬件 | 芯片完整型号、开发板版本、屏幕型号、接口与分辨率 |
| 软件 | SDK、LVGL、编译器版本，以及优化选项 |
| 时钟 | CPU、存储、显示接口和相关加速器时钟 |
| 内存 | 资源与缓冲区位置、Cache / MPU 属性、对齐方式 |
| 显示 | 像素格式、行跨度、刷新模式、缓冲数量、同步方式 |
| 负载 | 场景内容、更新区域、动画参数、加速后端 |
| 结果 | 绘制耗时、传输耗时、整帧耗时、CPU 占用、内存峰值、输入延迟 |
| 方法 | 计时边界、采样时长、重复次数、统计方式、异常记录 |

尚未测量的数据统一标记为“未测”，不以理论值或其他平台数据代替。

### 4.3 固定排障方法

```text
确认现象
    |
    v
缩小到可复现的最小场景
    |
    v
沿数据路径逐段采集证据
    |
    v
每次只修改与假设直接相关的配置
    |
    v
验证正确性，再比较性能
    |
    v
记录结论和适用条件
```

## 五、单篇文章的建议结构

并非每篇都需要包含代码。原理篇强调系统关系；实战篇必须说明平台和复现条件。

```markdown
# 第 N 篇：文章标题

## 本篇要解决的问题
## 适用平台、版本与前置知识
## 原理与数据路径
## 配置与实现（实战篇）
## 验证方法与结果
## 常见问题与排查
## 小结与下一篇
## 参考资料
```

写作时保持三条原则：

- **先解释职责，再解释寄存器或 API。**
- **先建立正确基线，再加入性能优化。**
- **先给出证据，再给出性能结论。**
