# 第 14 篇：PXP 实战——从单次处理到异步流水线

> 系列：[i.MX RT 图形系统实战](README.md)
>
> 上一篇：[认识 PXP——它能加速什么，不能加速什么？](13-pxp-capabilities.md)
>
> 下一篇：[GPU 与 VG-Lite 入门](15-gpu-vglite.md)
>
> 本篇目标：建立可验证的处理、完成和显示交接。本文提供实施流程和离线参考，不声称已经完成某块板卡的 PXP 测量。

## 1. 先跑独立处理，不立刻接 GUI

从固定输入和独立输出开始，避免把 GUI、显示扫描和 PXP 同时作为未知量。

一条基线是：

```text
准备输入 -> 检查配置 -> 维护缓存 -> 启动
    -> 等待处理完成或错误 -> 校验输出 -> 交给显示
```

先做复制和固定混合，再增加变换。保留每次操作的输入、配置、输出和错误状态。

## 2. 同步基线需要完整收尾

使用 SDK 初始化、输入/输出配置与启动接口时：

- 清理陈旧完成状态，准备本次请求编号。
- 检查每项有返回值的配置或启动结果。
- 等待完成时同时检查实际错误状态。
- 给等待明确的超时。
- 超时后停止/重置并确认访问终止，再释放缓冲。

不能仅检查完成位并无限忙等，也不能把 AXI 读写错误当作普通完成。

NXP 的示例适合观察路径；产品要补齐故障处理和拥有权。

## 3. 把像素正确性变成独立验收

| 操作 | 应验证 |
| --- | --- |
| 复制 | 有效区一致，padding 和边界不被破坏 |
| 转换 | 红绿蓝与量化结果 |
| 混合 | Alpha 端点、中间值与背景 |
| 旋转 | 非对称坐标、输出宽高与 pitch |
| 缩放 | 边缘、采样策略、容差 |

为输出周围放置受控哨兵区，可以检测越界，但哨兵区不能与设备维护区域内的无关数据混用。

对硬件输出做 CPU 校验前，先确认写入完成并处理缓存可见性。

## 4. 一个离线混合参考

以下模型对存储的 8 位通道做直 Alpha 混合，再量化成 RGB565。不模拟 PXP 的具体舍入、预乘或颜色转换。

```python
foreground = (255, 0, 0)
background = (0, 0, 255)

for alpha in (0, 128, 255):
    blended = tuple(
        (fg * alpha + bg * (255 - alpha) + 127) // 255
        for fg, bg in zip(foreground, background)
    )
    r, g, b = blended
    rgb565 = ((r >> 3) << 11) | ((g >> 2) << 5) | (b >> 3)
    print(f"alpha={alpha}: RGB={blended}, RGB565=0x{rgb565:04X}")
```

输出：

```text
alpha=0: RGB=(0, 0, 255), RGB565=0x001F
alpha=128: RGB=(128, 0, 127), RGB565=0x800F
alpha=255: RGB=(255, 0, 0), RGB565=0xF800
```

要把这作为硬件参考，应先对齐 Alpha 模式、通道顺序、舍入和输出格式。若采用预乘数据，不能继续使用相同输入解释。

## 5. 异步不是简单地删掉等待循环

真正异步接口要保存足够长寿命的请求状态：

| 状态 | 拥有者 | 允许做什么 |
| --- | --- | --- |
| FREE | 分配方 | 准备下一请求 |
| CONFIGURING | 提交方 | 设置本次输入输出 |
| RUNNING | PXP | CPU 不改源和目标 |
| COMPLETE | 收尾方 | 建立结果可见性 |
| DISPLAY_OWNED | 显示方 | 等待显示消费者释放 |
| FAILED | 恢复方 | 明确中止与重绘 |

处理完成只释放 PXP 拥有权，不代表显示扫描已经结束。

源可以在 PXP 不再读取后复用；输出需要等它的全部下游消费者释放。

## 6. 中断只传递真实状态

中断中读取完成与错误，按 SDK 语义清除，通知处理任务。

请求编号、队列状态和事件必须受正确同步保护。一个 `volatile bool` 不自动实现安全的多任务队列。

任务完成缓存维护、状态转移、显示提交或恢复。不要在中断中进行长时间校验或无边界等待。

重置发生后，陈旧事件不能错误地完成下一请求；需要状态或代次检查。

## 7. 双帧与流水线

```text
显示：扫描 A ---------------- 扫描 B
PXP：处理 B -> B 就绪          处理 A
软件：        提交 B、等 A 释放
```

PXP 不能在 A 仍被扫描时写 A。即使 B 处理只需短时间，也要遵守显示边界。

若显示接口按区域发送而非保留帧，释放事件的含义不同。沿用显示端口的真实契约，而不是统一叫“VSYNC 完成”。

LVGL 9.2.0 的 `lv_pxp_run()` 包装包含运行与等待；不能只看名称就认定调用后立即返回。

## 8. 性能测量边界

分别测量配置、缓存、处理、等待、显示交接和总更新时间。

| 指标 | 回答 |
| --- | --- |
| PXP 执行时间 | 硬件处理本身多快 |
| CPU 忙时间 | 释放了多少计算资源 |
| 请求到可复用 | 缓冲要被占用多久 |
| 输入到可见变化 | 用户实际等待多久 |

比较同步和异步时，场景、格式、输出质量与显示策略保持一致。

## 9. 小结

可靠 PXP 实战要完成“提交—运行—完成—显示—释放”的全链路，不能止于启动寄存器或一次正确图片。
