# 第 19 篇：让 LVGL 使用 PXP / GPU

> 系列：[i.MX RT 图形系统实战](README.md)
>
> 上一篇：[理解 LVGL 的刷新与绘制机制](18-lvgl-refresh.md)
>
> 下一篇：[触摸输入、RTOS 与线程安全](20-touch-rtos.md)
>
> 本篇目标：在 LVGL 9.2.0 中核对后端集成和实际任务派发。本文不把“宏打开”或软件模拟当作硬件加速成功。

## 1. 加速接入有六道条件

```text
芯片具有硬件
 -> SDK 驱动与初始化可用
 -> LVGL 后端版本匹配
 -> 内存/格式/对齐满足
 -> 实际任务被接收
 -> 完成与显示同步正确
```

任何一道未通过，都不能宣布 GUI 已实现硬件加速。

先保留软件基线和可比较场景，再逐项启用。

## 2. 核对配置名，而不是复制网上一组宏

LVGL 9.2.0 中有以下不同后端入口：

| 配置 | 源码路径 |
| --- | --- |
| `LV_USE_DRAW_PXP` | `src/draw/nxp/pxp` |
| `LV_USE_DRAW_VGLITE` | `src/draw/nxp/vglite` |
| `LV_USE_DRAW_VG_LITE` | `src/draw/vg_lite` |

最后两项不是别名，其初始化、线程、驱动版本和功能可能不同。

按 SDK 提供的适配选定一项 GPU 路径，不同时盲目启用。

软件后端也需要保持配置一致，为不支持任务提供正常路径。

## 3. 后端初始化还需要板级资源

检查：

- 时钟、电源、复位和内存。
- 实际驱动及编译选项。
- 中断、优先级与 OSAL。
- 目标缓冲和资源分配机制。
- Cache 维护与完成通知。

PXP 的默认中断初始化可能涉及 RTOS 允许的中断优先级。GPU 也可能依赖驱动工作区和特定平台初始化。

不能只链接 draw 源文件就假定这些条件齐全。

## 4. 从任务评估理解回退

在 9.2.0 PXP 后端中，简单填充、图像和图层有各自条件。圆角、渐变、某些变换/透明组合可能走软件。

VG-Lite 后端同样检查目标和源格式、芯片特征及任务类型。

| 情况 | 正常处理 |
| --- | --- |
| 后端不支持该任务 | 由支持它的其他后端执行 |
| 内存/驱动条件错误 | 明确报告并修正 |
| 硬件运行失败 | 故障处理与结果恢复 |

正常回退不等于忽略运行错误。硬件失败后的目标可能已经被部分写入。

## 5. 对齐不能只检查帧缓冲首地址

还需要检查：

- 图片数据地址和 stride。
- 临时图层的分配。
- 裁剪后区域及变换后的尺寸。
- 输出格式和缓存行边界。

9.2.0 PXP 后端的某些变换会检查图像尺寸为 16 的倍数；这是特定后端路径，不是所有绘制任务或所有 PXP 的统一约束。

不要把图片简单补零后忽略新尺寸、透明边缘和逻辑坐标。资源转换必须保持视觉语义。

## 6. 证明实际派发

可以使用：

1. 后端初始化和任务接受计数。
2. 支持/拒绝的任务类型与原因。
3. 硬件启动和完成事件。
4. 软件回退计数。
5. 同一场景的总时间与 CPU 忙时间。

内部任务标识和评分属于版本相关实现，不应该硬编码成产品配置。

先用已确认可接收的普通矩形或兼容图片验证，再添加复杂样式。

## 7. 验证任务与完成顺序

混合 CPU/GPU 绘制时，多个任务可能访问同一图层。依赖和可见性由框架与适配共同保证。

不应在应用外部增加一个独立 GPU 队列，又同时让 LVGL 使用同一资源而不串行管理。

后端完成、flush 交接和显示扫描结束是不同边界。把启动调用计时当作加速耗时，会得到误导数字。

## 8. 一份接入验收表

| 项目 | 所需证据 |
| --- | --- |
| 版本 | SDK、LVGL、驱动与芯片配置 |
| 初始化 | 时钟/工作区/中断有效 |
| 覆盖 | 任务类型与回退比例 |
| 正确性 | 图像、Alpha、边界与变换对照 |
| 生命周期 | CPU/后端/显示交接 |
| 性能 | 总帧时间、CPU、内存、延迟 |
| 故障 | 超时与部分结果恢复 |

每个未测项保留“未测”。不要只展示一个提高的 FPS，却隐藏画质变化或错误。

## 9. 小结

LVGL 硬件加速需要版本、资源、任务选择和同步四层同时成立。
