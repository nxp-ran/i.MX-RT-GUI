> 本篇目标：区分缓冲数量、刷新模式和同步策略，用拥有权模型解释撕裂。时间示意不是硬件测量。

## 1. 为什么多一块 RAM 不自动消除撕裂？

撕裂通常意味着一次可见扫描中混合了不同更新时刻的内容。

连续扫描时，显示控制器读到上半部分后，生产者修改后半部分，就可能出现新旧画面边界。

带 GRAM 的屏幕也可能在扫描时接收新像素。因此，“SPI 屏有 GRAM”或“软件有双缓冲”都不是无撕裂保证。

```text
扫描方：读取旧内容 -------- 读取新内容
写入方：          修改画面
结果：同一次扫描不是同一个完整版本
```

关键是数据交接的时间，而不只是容量。

## 2. 三个独立选择

| 选择 | 问题 |
| --- | --- |
| 缓冲数量 | 有多少块独立可用内存？ |
| 刷新方式 | 局部、直接或完整重绘？ |
| 同步机制 | 什么时候传输、切换和释放？ |

两块小缓冲通常用于绘制与传输交替；两块完整显示帧可以用于前后台换帧。两者不能混称为同一种方案。

LVGL 的模式和驱动的显示架构必须匹配，不能仅通过设置第二个指针改变屏幕扫描行为。

## 3. 单显示帧的优点与代价

单帧节省容量，可以在低频或局部更新中满足需求。

但直接改写扫描帧时，要接受或控制扫描冲突。小区域也可能落在当前读取位置附近，不能因区域小就默认安全。

可以考虑：

- 在目标控制器允许的安全窗口内更新。
- 限制更新范围和执行时间。
- 根据产品需求接受可测量的撕裂风险。
- 改用完整后台帧或其他硬件机制。

不是所有面板都允许暂停扫描，也不能把停止扫描当作通用无撕裂方案。

## 4. 双显示帧的拥有权

典型过程：

```text
A: 正在扫描             B: 可绘制
                         |
                         v
                    B 完整准备好
                         |
                         v
                  请求在目标边界切换
                         |
                         v
                 确认 B 生效、A 被释放

B: 正在扫描             A: 可绘制
```

提交 B 后，A 和 B 都可能暂时不能修改：A 仍被扫描，B 已经交给下游。

一次普通 VSYNC 不一定确认某个具体请求生效。应使用驱动约定、当前地址或明确的释放回调，并核对事件时序。

不能在提交之后才清除等待状态，导致已经到来的事件丢失。

## 5. 局部双帧还有“旧内容”问题

假设 A 包含最新界面，B 比 A 旧一次更新。

如果只在 B 中修改当前按钮，再切换到 B，其他区域可能回退为旧内容。

因此，直接模式的双帧需要同步未一致区域，或确保下一后台帧完整重绘。

| 策略 | 收益 | 代价 |
| --- | --- | --- |
| 每次完整重绘后台帧 | 内容一致逻辑简单 | 绘制量大 |
| 同步脏区域 | 少改动场景可能更省 | 复制、状态和时序 |
| 保留单个显示帧，局部拷贝 | 容量较低 | 扫描冲突仍需管理 |

LVGL 9.2 DIRECT 双缓冲包含相应区域同步行为；移植时不要再盲目加一份整屏复制，也不要在它同步前提前释放硬件仍使用的帧。

## 6. GRAM 屏与 TE

局部传输链路中的两个源缓冲，只保护主控绘制与发送不互相覆盖。

它们没有为面板 GRAM 自动提供原子换帧。

TE 可以告诉软件特定扫描事件，但还需要：

- 正确理解 TE 模式。
- 核对扫描与写入方向。
- 计算更新区域的实际发送时长。
- 检查允许的窗口和控制器存储机制。

例如，单线 40 MHz 的 320 × 240 RGB565 整屏纯像素传输约 30.72 ms，已经超过 60 Hz 的 16.67 ms 帧周期。

从 TE 边沿开始并不能单独证明整屏更新无撕裂。

## 7. 三缓冲解决的是什么？

第三块完整帧可以减少生产者等待，但同时引入排队策略。

| 策略 | 适合关注 | 风险 |
| --- | --- | --- |
| FIFO 显示每帧 | 保留完整序列 | 输入延迟增加 |
| 优先最新就绪帧 | 低延迟交互 | 中间帧被丢弃 |
| 生产者等待空闲帧 | 资源和状态简单 | 限制吞吐 |

丢帧必须是明确策略并统计，不能覆盖正在读取或已提交的内存来“实现最新优先”。

帧池至少维护 FREE、DRAWING、READY、PENDING、SCANNING 状态，由明确拥有者转换。

## 8. 用测试区分问题

| 测试 | 目的 |
| --- | --- |
| 全屏交替纯色 | 检查原子换帧与混合边界 |
| 带编号移动矩形 | 识别重复、丢失和旧内容 |
| 两个独立变化区域 | 暴露双帧局部同步缺失 |
| 故意延长绘制/传输 | 检查错过边界时的行为 |
| 增加提交速度 | 检查队列上限与拒绝处理 |

同时记录请求编号、缓冲地址、事件和释放编号。人眼观察可以发现现象，但不足以证明每次交接都正确。

## 9. 小结

无撕裂依赖内容版本和扫描边界的一致性。缓冲数、模式、同步和队列策略需要共同设计。
