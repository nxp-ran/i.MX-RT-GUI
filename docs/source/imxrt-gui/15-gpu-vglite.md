# 第 15 篇：GPU 与 VG-Lite 入门〔适用型号〕

> 系列：[i.MX RT 图形系统实战](README.md)
>
> 上一篇：[PXP 实战](14-pxp-pipeline.md)
>
> 下一篇：[CPU、PXP、GPU 怎么选？](16-render-backend-selection.md)
>
> 本篇目标：理解二维 GPU 命令、图像、路径与同步。以 RT1170 产品能力和 LVGL 9.2.0 适配为参考；具体 API 仍需匹配所用 VG-Lite 驱动。

## 1. 先分清硬件和软件

GPU 是执行图形工作的硬件；VG-Lite 是相关 API/驱动栈，不是另一个并列外设。

```text
应用或 LVGL -> VG-Lite API -> 驱动/命令缓冲 -> GPU
                                                  |
                                                  v
                                             目标图像
```

本系列讨论二维 GUI，不把 MCU GPU 当作桌面三维显卡。

硬件版本、编译配置与驱动可能影响路径、滤波、格式和混合支持，不能根据“有 GPU”推断完整能力。

## 2. 图像与路径是两类输入

| 输入 | 描述 | 常见工作 |
| --- | --- | --- |
| Bitmap | 已有像素及布局 | Blit、缩放、旋转、混合 |
| Path | 几何轮廓与参数 | 填充、受支持的描边 |
| Draw target | 输出像素存储 | 接收结果，不等于面板 |

图片本身通常仍需读取；路径也可能需要曲线处理、tessellation 工作区和结果写入。

矢量不是零容量、零带宽。复杂图形要预算路径、工作区、缓存和离屏结果。

## 3. Transform、Clip 与 Blend

变换描述源或几何如何映射到目标。裁剪限制绘制范围，混合决定覆盖方式。

常见错误包括：

- 使用错误的坐标原点或变换顺序。
- 把矩阵变换和已经旋转的源重复应用。
- 裁剪坐标与目标区域不一致。
- 直 Alpha 和预乘 Alpha 混用。
- 驱动输出格式与后续消费者解释不一致。

尤其透明边缘出现暗边时，应检查 Alpha 和颜色语义，而不只检查“GPU 有没有运行”。

## 4. 最小执行生命周期

下面是逻辑调用流程，不是可以脱离板级驱动直接编译的初始化程序：

```text
初始化平台、GPU 与 VG-Lite
   -> 分配/映射驱动可访问的目标
   -> 准备图像或路径
   -> 提交 clear / blit / draw
   -> 按接口提交命令
   -> 等待执行完成并检查错误
   -> 交给 CPU 校验或显示
   -> 等消费者释放
   -> 释放图像/路径/工作区
```

`vg_lite_flush()` 与 `vg_lite_finish()` 一类接口表达提交和等待区别，但精确行为以实际版本为准。

不能在命令 API 返回后立即释放源图像、路径或目标，因为 GPU 可能尚未读取。

## 5. 分配器也是适配的一部分

`malloc()` 返回可访问 CPU 地址，不证明 GPU 能使用。

核对：

- 驱动分配或映射机制。
- 像素格式、stride 和地址对齐。
- 目标内存可达性与容量。
- CPU/GPU 的可见性和缓存维护。
- 图像、路径与工作区的独立生命周期。

缓冲区“映射成功”也不等于格式和实际尺寸正确。不要用不必要的强制转换掩盖描述符类型不匹配。

## 6. 为什么多个命令可以更快？

批量提交可能摊薄固定开销，让 GPU 连续执行。

但批量越大，可能增加：

- 命令和资源占用。
- 请求排队时间。
- 输入到显示延迟。
- 故障恢复复杂度。

不能把“flush 次数少”当作唯一性能目标。任务之间存在读写依赖时，顺序与必要同步不能省略。

## 7. 两个相近的 LVGL 后端名称

LVGL 9.2.0 配置中可以看到：

| 配置名 | 对应路径 |
| --- | --- |
| `LV_USE_DRAW_VGLITE` | `src/draw/nxp/vglite` |
| `LV_USE_DRAW_VG_LITE` | `src/draw/vg_lite` |

它们不是同一个拼写别名。

NXP SDK 适配、芯片版本、GPU 初始化、线程与缓存钩子应与选定后端一致。不要把两组宏同时打开，希望“加速更强”。

通用软件模拟或其他平台上的 VG-Lite 接口运行成功，也不能作为 RT1170 硬件 GPU 已工作的证据。

## 8. 一个逐级实验路线

| 阶段 | 内容 | 通过条件 |
| --- | --- | --- |
| 目标填充 | 固定颜色 | 目标像素与边界正确 |
| 图片复制 | 非对称彩色图 | 格式、stride、位置正确 |
| 变换 | 旋转与缩放 | 方向、滤波和裁剪符合约定 |
| 混合 | Alpha 端点与边缘 | 背景及透明语义正确 |
| 多命令 | 有依赖任务 | 结果与单次路径一致 |
| 显示交接 | 提交处理结果 | 生命周期与换帧正确 |

所有有错误返回的 API 都应检查。失败要记录并停止成功路径，在确认硬件不再访问后才释放资源。

## 9. 小结

GPU 加速不仅是多一个绘图函数，而是命令、内存、同步和输出语义的完整系统。
