# 第 23 篇：从瓶颈出发优化，而不是盲目开加速

> 系列：[i.MX RT 图形系统实战](README.md)
>
> 上一篇：[建立可信的 GUI 性能测试方法](22-performance-testing.md)
>
> 下一篇：[完整案例——做一个可交付的 i.MX RT GUI](24-complete-gui-case.md)
>
> 本篇目标：用证据选择优化位置，并验证没有牺牲画质、延迟或可靠性。下面案例是推演，不是实际板卡成绩。

## 1. 优化前先画时间线

把事件、绘制、传输、换帧等待和扫描连接起来。

```text
CPU 工作      ------
加速器工作         --------
像素传输                   ------------
显示等待                               ----
```

图中的长度必须用测量支持。CPU 主频、GPU 名称和理论 MB/s 都不能直接指出当前瓶颈。

观察有无重叠、队列等待、资源加载和错误。

## 2. 四类典型瓶颈

| 类型 | 证据 | 可考虑 |
| --- | --- | --- |
| 绘制 | 后端执行占关键路径 | 简化任务、兼容加速、资源预处理 |
| 接口 | 传输接近有效吞吐上限 | 减少面积、改进分块、合适接口 |
| 内存 | 负载相关等待/欠载 | 布局、拷贝、图层、访问竞争 |
| 同步/调度 | 执行短但排队长 | 通知、锁、帧策略、任务配合 |

多个瓶颈可能共存。优化一项后，需要重新测量，不能永久沿用原判断。

## 3. 推演一：SPI 全屏动画受接口限制

**现象：** CPU 更快填完画面，但整屏更新仍慢。

**证据：** 分段计时显示传输占主要时间；实测有效字节与接口时间接近链路预算。

**修改：**

- 检查是否需要整屏变化，利用真实无效区域。
- 减少逐像素软件间隔，使用已验证 DMA。
- 调整块大小和事务设置成本。
- 若需求确实持续全屏，重新评估接口方案。

**复测：** 使用同样动画和画质，检查有效传输量、总时间、CPU、撕裂和尾块正确性。

以 320 × 240 RGB565、单线 40 MHz 为理论例，纯像素已需 30.72 ms。缩短 CPU 时间不能突破这个传输量级。

## 4. 推演二：透明层增加了存储压力

**现象：** GPU 运行后 CPU 较空闲，但加入多层动画出现欠载。

**证据：** 显示错误与图层/其他总线负载相关，内存路径读写增加。

**修改：**

- 缩小真正需要 Alpha 的区域。
- 去掉重复整屏中间拷贝。
- 评估预合成与扫描合成的总流量。
- 检查资源与输出是否能合理分散访问。

**复测：** 不改变透明语义或滤波，检查异常计数、延迟、图层边界和相同业务负载。

不要通过让透明图像变不透明来报告“同场景加速”。

## 5. 推演三：线程等待比绘制更慢

**现象：** 绘制快、显示也能及时完成，但触摸跟手性差。

**证据：** 输入到 GUI 处理存在长等待，队列积压或持锁区阻塞。

**修改：**

- 让一个 GUI 拥有者消费状态。
- 对可合并数值使用最新快照。
- 将耗时 I/O 和解码移出不必要的持锁区域。
- 用完成通知替代固定长延时。
- 为不可丢离散事件保留明确队列。

**复测：** 输入延迟分布、事件是否丢失、页面寿命和业务实时性。

提高优先级可能把卡顿转移到网络或控制任务，不能只看 GUI。

## 6. 微优化的先后顺序

建议：

1. 减少根本不需要的工作。
2. 消除重复拷贝和错误刷新。
3. 改善任务与缓冲配合。
4. 使用兼容硬件后端。
5. 最后优化热点算法和指令。

如果每轮都重复加载同一图片，先处理资源生命周期，比改一个像素混合指令通常更直接。

但任何缓存策略都要有容量与失效，不将内存泄漏当作性能优化。

## 7. 避免三个危险捷径

| 捷径 | 为什么不可靠 |
| --- | --- |
| 提前报告 flush 完成 | 源仍可能被读，造成竞态 |
| 关闭所有错误/断言 | 隐藏故障，不降低根因成本 |
| 使用未核对超规格时钟 | 稳定性和寿命条件不成立 |

同样，不为了减少维护开销就忽略 Cache，不为了减少等待就覆盖正在扫描的帧。

## 8. 每次优化保存一张对照表

| 项目 | 修改前后都记录 |
| --- | --- |
| 条件 | 版本、时钟、画质、负载 |
| 正确性 | 像素、范围、Alpha、错误 |
| 吞吐 | 完成周期和分布 |
| 响应 | 输入到可见变化 |
| 资源 | CPU、堆栈峰值、缓冲 |
| 可靠性 | 队列、超时、恢复、重复运行 |

一次改变一个直接相关因素，重复测量。保留可能退化的场景，不只报告平均收益。

## 9. 小结

优化不是尽可能打开硬件开关，而是对关键路径减少实际成本，并保持行为和可靠性。
