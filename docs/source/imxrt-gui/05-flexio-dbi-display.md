# 第 5 篇：8080 / DBI 并口屏——利用 FlexIO 等资源实现显示

> 系列：[从点亮屏幕到高性能 GUI：i.MX RT 图形系统实战](README.md)
>
> 上一篇：[SPI / QSPI 屏——从发送命令到局部刷新](04-spi-qspi-display.md)
>
> 下一篇：[RGB 屏——理解像素时钟与连续扫描](06-rgb-display.md)
>
> 本篇目标：理解 8080 式并口的命令、数据和读写时序，并把 FlexIO、DMA、区域刷新组织成一条可靠的数据路径。
>
> 适用范围：以带显示控制器和 GRAM 的 8 位或 16 位 8080 式接口为模型。具体 i.MX RT 的引脚、FlexIO 实例、DMA 路由和面板支持需要分别核对。算例与离线脚本不代表板卡实测。

## 1. 从串行屏到并口屏，什么变了？

在[第 4 篇](04-spi-qspi-display.md)中，主控通过串行接口设置窗口，再把像素写入屏幕 GRAM。

换成 8080 式并口后，这个逻辑通常仍然成立：

```text
绘制区域 -> 设置目标窗口 -> 发送像素 -> 屏幕 GRAM -> 面板扫描
```

改变的是传输方式：数据不再逐位经过一根线，而是在一组数据线上按读写周期传输。

因此，并口屏并不自动变成“主控持续扫描整帧”的 RGB 屏。带 GRAM 的屏幕仍然可以保存画面，主控只更新变化区域。

| 维度 | 常见 SPI 屏 | 本篇的 8080 式并口屏 |
| --- | --- | --- |
| 数据传输 | 串行时钟逐位发送 | WR / RD 周期传输一个总线字 |
| 命令与数据 | D/C 或传输字内命令位 | RS / D/C |
| 图像保存 | 屏幕 GRAM | 屏幕 GRAM |
| 局部更新 | 地址窗口 | 地址窗口 |
| 主控关注点 | 时钟、字节序、事务边界 | 总线位宽、建立保持时间、选通周期 |

本篇讨论常见的 Intel 8080 式时序。DBI 是更广的显示总线接口概念；不是所有 DBI 模式都采用这里的信号和操作方式。

## 2. 先把每根信号的职责讲清楚

| 信号 | 常见作用 | 必须确认的条件 |
| --- | --- | --- |
| D[7:0] / D[15:0] | 数据总线 | 模组模式、位映射和逻辑电平 |
| CS | 片选 | 有效极性和事务保持要求 |
| RS / D/C | 命令与数据选择 | 电平含义、建立与保持要求 |
| WR | 写选通 | 有效极性、锁存边沿、脉宽和周期 |
| RD | 读选通 | 读周期、输出使能和总线释放时间 |
| RESET | 控制器复位 | 供电后的时序与延时 |
| BL | 背光控制 | 驱动电路与控制方式 |
| TE | 可选扫描同步输出 | 事件含义和允许更新窗口 |

一些只写设计不需要读取像素，但不能把未使用的 RD 随意悬空。应按模组资料把它保持在非有效状态。

同样，屏幕控制器支持多种接口，不代表模组已经选择了你需要的模式。接口模式可能由硬件绑定位决定。

## 3. 一个写周期，包含的不只是 WR 脉宽

以一种常见模型为例：WR 为低时执行写周期，在上升沿锁存数据。实际锁存边沿必须以目标控制器资料为准。

```text
时间 ->

CS       __________有效____________________
RS       ----命令或数据选择，保持稳定---------
DATA     -----[有效总线字]-------------------
WR       --------\________/-----------------
                  写脉冲   锁存边沿
```

需要核对至少四类约束：

1. 数据和 RS 在锁存前的建立时间。
2. 锁存后的保持时间。
3. WR 的低电平和高电平最小时间。
4. 连续写周期的最小间隔。

如果控制器要求最小写周期 100 ns，就不能只检查 WR 低脉宽满足要求，然后生成总周期 60 ns 的波形。

读周期还涉及数据总线方向切换。读取结束后，必须等待屏幕释放总线，再由主控驱动；不能让两端同时输出。

逻辑分析仪有助于观察命令与数据顺序，建立时间、边沿质量和电平裕量则需要适当的波形测量。

## 4. 8 位与 16 位总线，不能只看引脚数量

对 RGB565，一个像素有 16 位。

### 4.1 8 位接口

在本例“高字节先写”的约定下，红色像素 `0xF800` 需要两个写周期：

```text
第一个周期：D[7:0] = F8
第二个周期：D[7:0] = 00
```

### 4.2 16 位接口

若面板配置和数据位映射匹配，一个写周期可以提交：

```text
D[15:0] = F800
```

这不意味着所有命令和参数也都能按两个字节随意拼接。

例如，某个控制器在 16 位接口下可能仍要求每个 8 位命令参数占用一个总线周期，高位按其规定处理。应核对面板协议和驱动，不把两个地址参数合成一个 16 位像素字来发送。

### 4.3 三层宽度分别核对

| 层次 | 需要回答的问题 |
| --- | --- |
| 像素格式 | 一个像素包含多少有效位？ |
| 物理接口 | 每个 WR 周期传输多少位？ |
| 内存与 DMA | 源数据以字节、半字还是字读取？ |

16 位总线能减少 RGB565 的像素选通次数，但收益仍取决于 WR 速率、驱动间隙、存储访问和面板限制。

## 5. FlexIO 怎样把数据变成并口时序？

FlexIO 是可配置外设资源，不是软件把普通 GPIO 挨个写一遍的同义词。

一个典型发送路径是：

```text
像素 RAM
    |
    v
CPU / DMA 写入移位器缓冲
    |
    v
FlexIO 移位器 + 定时器
    |
    v
并行数据线 + WR
    |
    v
屏幕控制器
```

移位器负责组织数据，定时器产生相应时序，CS 和 RS 可能通过板级 GPIO 回调控制。

本次核对的 NXP MCULCD 驱动明确提供了 8 位和 16 位总线配置，并用一个起始索引描述连续的 FlexIO 数据引脚。

这带来几项实际检查：

- 封装是否引出了所需的数据线。
- IOMUX 是否能形成驱动要求的引脚组合。
- 选用的移位器数量和索引是否符合驱动限制。
- 定时器、WR 和 RD 引脚是否可用。
- 目标 FlexIO 实例是否存在需要的 DMA 请求。
- 请求能否路由到选用的 DMA 通道。

**有 FlexIO，不等于任意一组引脚和任意 DMA 通道都能组成显示接口。**

### 5.1 时钟参数的单位尤其容易弄错

在本次引用版本的 `flexio_mculcd_config_t` 中，`baudRate_Bps` 描述的是所有数据线合计的位速率，而不是 WR 选通频率。

这类 API 参数名不能直接当作波形测量值。应结合该版本的分频实现，计算或测量实际 WR 周期。

FlexIO 模块时钟、总线访问时钟与写周期也不是同一个频率。

## 6. 从 SDK 现有分层开始，不重复造驱动

NXP 公开 MCULCD 示例把功能拆成：

```text
面板组件
   -> 命令发送
   -> 参数发送
   -> 像素内存写入
          |
          v
FlexIO MCULCD + eDMA
```

其中短命令和参数可以使用阻塞接口，像素采用 eDMA。

但示例中的像素写入包装函数仍然等待 DMA 完成，因此：

> 使用了 DMA，不代表上层调用已经是异步的。

SDK 示例适合学习 API 的组织方式，不能照搬其中无限等待和简化错误处理作为产品方案。

这里引用的通用示例支持列表也不等于它已经支持所有 i.MX RT 开发板。仍要检查目标 SDK 的板级配置和相应实例能力。

## 7. 按窗口刷新时，数据与坐标仍要一致

假设更新坐标 `(20, 30)`、大小 `100 × 40`，RGB565：

```text
列范围：20 到 119
行范围：30 到 69
像素数：100 × 40 = 4,000
有效数据：4,000 × 2 = 8,000 B
```

步骤依旧是：

1. 校验逻辑坐标、可见区域偏移和源数据范围。
2. 取得完整屏幕事务的独占访问。
3. 设置列与行窗口。
4. 开始写入像素。
5. 按真实长度传输。
6. 确认传输完成并交回缓冲区。

如果源图像来自完整帧，局部区域通常带有行间距，不能直接连续发送整个矩形字节数。

可以按行发送、打包区域，或使用目标 DMA 支持的描述方式。每种方案都需要核对窗口续写与 CS 边界。

并行接口提高传输能力，却不会自动修正坐标、stride 或字节数量错误。

## 8. DMA 完成后，最后一个 WR 周期结束了吗？

要分别确认：

- DMA 何时停止读取源内存。
- FlexIO 移位器何时把最后的数据送出。
- WR、CS 和 RS 何时允许改变。
- 上层何时可以提交下一笔事务。

本次引用的 MCULCD 驱动头文件专门说明了末尾移位完成等待：该实现使用软件等待保证末尾数据送出，等待不足可能丢失最后几个字节。

因此，不应为了提高性能盲目缩短内部等待，更不能仅看到 DMA 计数归零就立即取消片选。

对于真正异步的 GUI 端口：

- 源缓冲区及仍被使用的参数保持有效。
- CPU 写入必须按实际内存路径对 DMA 可见。
- 完成事件交给正确的拥有者处理。
- 启动失败、超时和中止状态必须显式通知。
- 确认所有消费者释放后才能复用。

双缓冲的收益来自绘制与传输重叠，而不是提前报告完成。

## 9. 算一笔并口账，并和 SPI 比较

下面假设：

- 分辨率 320 × 240。
- RGB565。
- 并口每个有效写周期为 100 ns。
- SPI 为单数据线、40 MHz。
- 不计命令、空闲间隔、绘制、DMA 设置和扫描同步。

| 传输方式 | 理想像素带宽 | 整屏纯像素时间 | 100 × 40 区域时间 |
| --- | --- | --- | --- |
| 单线 SPI，40 MHz | 5 MB/s | 30.72 ms | 1.60 ms |
| 8 位并口，100 ns/周期 | 10 MB/s | 15.36 ms | 0.80 ms |
| 16 位并口，100 ns/周期 | 20 MB/s | 7.68 ms | 0.40 ms |

100 ns 是算例假设，不是任意面板都允许的配置。

同周期下，16 位接口的 RGB565 像素吞吐是 8 位的两倍；实际系统是否达到相同比例，仍需测量。

以下脚本可以离线复算，不访问硬件：

```python
width, height = 320, 240
bytes_per_pixel = 2
frame_bytes = width * height * bytes_per_pixel
region_bytes = 100 * 40 * bytes_per_pixel
cycle_ns = 100

rates = [
    ("SPI 1-line 40 MHz", 40_000_000 / 8),
    ("DBI 8-bit", 1_000_000_000 / cycle_ns),
    ("DBI 16-bit", 2 * 1_000_000_000 / cycle_ns),
]

for label, rate in rates:
    frame_ms = frame_bytes / rate * 1000
    region_ms = region_bytes / rate * 1000
    print(
        f"{label}: {rate / 1_000_000:.2f} MB/s, "
        f"frame {frame_ms:.2f} ms, region {region_ms:.2f} ms"
    )
```

输出：

```text
SPI 1-line 40 MHz: 5.00 MB/s, frame 30.72 ms, region 1.60 ms
DBI 8-bit: 10.00 MB/s, frame 15.36 ms, region 0.80 ms
DBI 16-bit: 20.00 MB/s, frame 7.68 ms, region 0.40 ms
```

这些是像素传输上限，不是可见 GUI 帧率。

## 10. 一套最小验证顺序

| 阶段 | 测试内容 | 通过标准 |
| --- | --- | --- |
| 接口 | 命令、参数和一小块像素 | CS、RS、WR 顺序正确 |
| 格式 | 红绿蓝、黑白、交替像素 | 通道、位宽和像素顺序正确 |
| 范围 | 四角、单行、非整块高度区域 | 无偏移、越界和尾部残留 |
| 数据路径 | 阻塞与 DMA 显示相同图案 | 输出一致，无末尾丢字 |
| 生命周期 | 连续交替发送不同图案 | 无提前覆盖或事务交错 |
| 负载 | 加入典型 CPU 与存储负载 | 无传输错误，耗时可解释 |

性能表至少分别记录命令设置、像素传输和完整更新耗时，附上实测 WR 周期、有效字节数、CPU 占用及缓冲容量。

如果采用 TE，应验证实际写入和扫描关系。即使像素传输快，也不能只靠“从 TE 边沿开始”证明没有撕裂。

## 11. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 指令似乎有效，像素颜色不对 | 接口模式、像素格式、数据位映射 |
| 每两个像素规律性异常 | DMA 宽度、字节/半字排列、总线打包 |
| 最后几个像素丢失 | 移位完成等待、CS/RS 提前变化 |
| 小窗口正常，大窗口出错 | DMA 长度、续写方式、源 stride |
| 阻塞正常，DMA 不工作 | 实例请求、DMAMUX、通道和地址可达 |
| 提速后偶发花屏 | 写周期、建立保持时间、波形与信号完整性 |
| CPU 占用仍然很高 | 上层忙等、转换或区域打包成本 |

遇到问题，先恢复最小正确路径，再逐项增加 DMA、提速和流水线，不同时修改多个无关参数。

## 12. 小结

8080 式并口的核心不是“多几根数据线”，而是满足面板读写时序，并把数据打包、FlexIO 资源和缓冲区交接结合起来。

- 带 GRAM 的并口屏仍然适合局部更新。
- 总线位宽、像素格式与 DMA 宽度要分别核对。
- DMA 完成不自动表示最后一个选通周期结束。
- 优先复用 SDK 分层，并为产品补齐超时和错误处理。
