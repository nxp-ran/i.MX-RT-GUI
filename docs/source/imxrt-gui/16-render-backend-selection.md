> 本篇目标：用相同语义、端到端时间和资源代价选择执行后端。文中时间参数是数学假设，不代表芯片成绩。

## 1. 先问能不能做，再问快不快

选择顺序应该是：

```text
操作与画质要求
  -> 硬件/驱动/后端支持
  -> 内存与生命周期可行
  -> 输出正确
  -> 比较端到端成本
```

不支持的操作标记为不适用，不能用近似效果冒充等价比较。

CPU 软件路径仍然重要：它提供基线和不被硬件接收任务的执行方式。

## 2. 真正要比较的成本

| 成本 | CPU 路径 | 硬件路径 |
| --- | --- | --- |
| 像素计算 | 软件执行 | 硬件执行 |
| 提交与配置 | 可能较低 | 驱动、描述符和寄存器 |
| Cache | 视数据方向而定 | 交接可能更多 |
| 移动与转换 | 也可能存在 | 格式/地址不兼容时增加 |
| 等待 | 软件执行时间 | 任务、事件和完成同步 |
| 显示 | 同样需要 | 不能省掉下游限制 |

只计从 Start 到 IRQ，会漏掉硬件路径的准备与交接成本。

## 3. 简化的交叉点模型

假设 CPU 每像素耗时 40 ns，硬件每像素 8 ns，但固定提交成本为 80 us：

```text
T_cpu(N) = 40 × N ns
T_hw(N) = 80,000 + 8 × N ns
相等时 N = 80,000 / (40 - 8) = 2,500 pixel
```

小区域可能 CPU 更快，大区域可能硬件更快。

以下脚本复算这个假设，不是实测：

```python
cpu_ns = 40
hardware_ns = 8
setup_us = 80
crossing = setup_us * 1000 / (cpu_ns - hardware_ns)

print(f"Break-even: {crossing:.0f} pixels")
for side in (20, 100):
    pixels = side * side
    cpu_us = pixels * cpu_ns / 1000
    hardware_us = setup_us + pixels * hardware_ns / 1000
    print(f"{side}x{side}: CPU {cpu_us:.1f} us, hardware {hardware_us:.1f} us")
```

输出：

```text
Break-even: 2500 pixels
20x20: CPU 16.0 us, hardware 83.2 us
100x100: CPU 400.0 us, hardware 160.0 us
```

真实 Cache、带宽、批量和同步成本不一定线性。因此交叉点需要按场景重新测量，不能把 2,500 写成产品阈值。

## 4. 一个后端选择表

| 工作 | 初步考虑 | 必须核对 |
| --- | --- | --- |
| 小块填充 | CPU 或已集成硬件 | 固定开销 |
| 大幅图像转换 | PXP 等像素引擎 | 格式组合、带宽 |
| 简单旋转/缩放 | 支持的 PXP/GPU | 角度、尺寸、滤波 |
| 路径与复杂形状 | GPU 或软件 | 几何与画质支持 |
| 不兼容任务 | 软件路径 | 正确回退与成本 |

“回退”应由框架能力判断正常选择，不应在硬件运行失败后静默假装成功。

硬件错误可能意味着目标内容已经部分写入，不能随意从中间接着软件绘制。

## 5. 相同像素数不代表相同内存流量

填充可能只写目标；复制读源写目标；透明混合还读背景。

比较时固定：

- 源和目标格式、位置与 stride。
- Alpha 模式和颜色语义。
- 变换与滤波。
- 内存区域、Cache 和时钟。
- 是否包含资源解码、复制与显示同步。

GPU 更快完成计算，但若与显示竞争 RAM，整帧收益可能很小甚至变差。

## 6. 吞吐与 CPU 可用时间分开看

硬件路径未提高 FPS，也可能降低 CPU 忙时间，给通信或控制留余量。

相反，忙等硬件完成可能让 CPU 利用率仍很高。

需要同时报告：

| 指标 | 用途 |
| --- | --- |
| 执行与总时间 | 判断吞吐 |
| CPU 忙时间 | 判断系统余量 |
| 峰值 RAM | 判断容量代价 |
| 输入延迟 | 判断交互 |
| 输出正确性与错误 | 判断可靠性 |

不能只根据某一个指标宣称“硬件一定更好”。

## 7. 实验与决策记录

先在独立操作中建立基线，再在相同 GUI 场景中比较。

测试小/中/大区域、不同透明度、冷/热资源和典型业务负载。报告分布和异常，而不是只挑最快一次。

若某项后端没有支持，表格中写“不适用”，同时保留软件基线。所有板级数据在实际测量前都标为“未测”。

## 8. 小结

最合适的后端由正确性、固定开销、每像素代价、内存竞争与系统目标共同决定。
