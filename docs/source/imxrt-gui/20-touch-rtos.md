> 本篇目标：让输入、业务和 LVGL 9.2.0 稳定协作。坐标算例是软件模型，不是触摸控制器校准结果。

## 1. 触摸到界面有两条路径

```text
触摸中断/采样 -> 输入状态 -> LVGL 输入读取 -> 事件 -> 界面

传感器/通信 -> 业务模型 -> GUI 消息 -> 界面
```

这两条路径最后都影响 GUI，但不应在任意任务或中断直接并发修改对象。

LVGL 默认不是线程安全的。控件更新、页面切换和资源生命周期都需要一致的拥有者或锁。

## 2. 输入回调报告状态，而不只是一个坐标

触摸输入至少需要：

- 是否按下。
- 有效坐标。
- 状态更新的时间。
- 读失败与无触点的区别。

松开时要报告 RELEASED，避免控件长期保持按下。

I²C/SPI 读取错误不能静默当作“没有触摸”。应记录输入故障，并按项目策略释放、重试或停止设备。

输入回调不应无限等待，也不应执行耗时页面重建。

## 3. 校准、方向和显示 offset

处理顺序需要明确：

```text
原始坐标
  -> 校准与有效范围
  -> 屏幕方向变换
  -> 物理显示与逻辑区域映射
  -> LVGL 坐标
```

不能在驱动和 LVGL 端口重复旋转，也不能忽略有效显示区域 offset。

若触摸设备已经输出最终像素坐标，就不要再按原始 ADC 范围缩放。

## 4. 一个离线映射例子

假设原始范围为 x=200..3800、y=100..3900，映射到 800 × 480，然后顺时针旋转 90 度，得到 480 × 800。

这采用整数向下取整，不代表真实触摸滤波方法：

```python
def map_touch(raw_x, raw_y):
    if not (200 <= raw_x <= 3800 and 100 <= raw_y <= 3900):
        raise ValueError("Touch sample is outside the assumed calibration range.")
    x = (raw_x - 200) * 799 // 3600
    y = (raw_y - 100) * 479 // 3800
    return 479 - y, x

for point in ((200, 100), (2000, 2000), (3800, 3900)):
    print(f"{point} -> {map_touch(*point)}")
```

输出：

```text
(200, 100) -> (479, 0)
(2000, 2000) -> (240, 399)
(3800, 3900) -> (0, 799)
```

实际应验证四角、中心、边界和拖动。噪声越界的钳位/拒绝策略应明确，不能无日志地掩盖校准错误。

## 5. 推荐的单 GUI 拥有者结构

| 上下文 | 工作 |
| --- | --- |
| 触摸中断 | 通知采样，必要时轻量记录 |
| 输入采样任务 | 总线读取、校准、状态快照 |
| 业务任务 | 更新领域数据、发送消息 |
| GUI 任务 | 消费消息、修改控件、运行 handler |
| 显示完成中断 | 目标端口允许的通知或完成操作 |

消息中的数据要有稳定生命周期。不要发送栈上的字符串指针后立刻返回。

连续数值可以选择最新快照，离散点击/控制事件通常不能随意丢弃。队列满要有背压、计数或明确拒绝，不静默丢重要状态。

## 6. 使用锁的另一种结构

如果确实要多个任务调用 LVGL，应使用统一互斥规则。

LVGL 9.2 的 OSAL 提供 `lv_lock()` / `lv_unlock()`；相应 OS 配置下 handler 内部也使用锁。不能把不同互斥对象混用，也要避免重复获取非递归锁。

事件和 LVGL timer 回调已经在处理上下文中执行。不要在持锁期间等待一个只能由同一 GUI 任务处理的结果，造成死锁。

锁只保护软件并发，不解决 DMA/Cache 一致性。

## 7. 中断与时间基准

官方 9.2 文档允许特定接口如 `lv_tick_inc()` 和 `lv_display_flush_ready()` 在适当中断契约中使用，但不意味着其他 LVGL API 都可在 ISR 调用。

`lv_display_flush_ready()` 仍必须代表真实交接，且与端口使用的等待机制一致。

FreeRTOS tick 频率、宽度和转换要明确；不应把非 1,000 Hz tick 直接当毫秒。

中断优先级还必须符合所用 RTOS 的可调用通知规则。

## 8. 输入延迟怎样测？

记录采样、事件处理、绘制完成、提交和可见变化。

| 阶段 | 可能的延迟 |
| --- | --- |
| 输入 | 轮询、总线与滤波 |
| GUI | 调度、锁、消息队列 |
| 绘制 | CPU/硬件任务 |
| 显示 | 传输、等待边界、扫描 |

降低触摸轮询间隔，不一定解决绘制或排队瓶颈；提高 GUI 优先级也可能损害业务实时性。

## 9. 验证与小结

检查点击、长按、快速点击、拖动、松开、边缘、换页中输入以及总线错误。

再加入通信、动画和资源加载，核对队列、锁等待和错误恢复。
