> 本篇目标：按 LVGL 9.2.0 管理资源格式、解码、字体与生命周期。容量是预算，真实资源需用实际转换器输出验证。

## 1. 资源经过哪些阶段？

```text
原始图片/授权字体
   -> 离线转换与裁剪
   -> Flash 或文件
   -> 读取/解码/缓存
   -> 绘制后端
   -> 像素缓冲
```

每一阶段都有格式和容量。PNG 文件小，不意味着运行时只占相同大小 RAM。

字体与图片应确认使用和分发许可；本篇不提供第三方字体文件。

## 2. 图片格式按用途选择

| 类型 | 适合 | 代价 |
| --- | --- | --- |
| RGB565 位图 | 不透明图像、低容量输出 | 色深与无 Alpha |
| ARGB8888 | 透明图像与合成 | 容量和读写增加 |
| A4/A8 掩模 | 单色图标或字形 | 色彩由绘制状态决定 |
| 压缩图片 | 节约存储或更新资源 | 解码、缓存和后端兼容 |

选择与实际后端匹配的解码结果，可能减少运行时转换。不要只为磁盘容量最小而让每帧重新解码。

图片全局透明度、像素 Alpha 和预乘状态是不同概念，应保留一致的语义。

## 3. 9.2.0 图像描述不能套旧结构

该版本的 `lv_image_dsc_t` 包含 header、数据长度和数据指针；header 有 magic、format、尺寸与 stride 等。

旧版示例中的字段与创建函数可能已经不同，应以固定版本头文件和转换器为准。

下面是一个完整的 2 × 2 RGB565 常量图像，行跨度 4 B，像素分别为红、绿、蓝、白：

```c
#include "lvgl.h"

static _Alignas(4) const uint8_t icon_pixels[] = {
    0x00, 0xF8, 0xE0, 0x07,
    0x1F, 0x00, 0xFF, 0xFF
};

const lv_image_dsc_t ui_icon = {
    .header = {
        .magic = LV_IMAGE_HEADER_MAGIC,
        .cf = LV_COLOR_FORMAT_RGB565,
        .w = 2,
        .h = 2,
        .stride = 4
    },
    .data_size = sizeof(icon_pixels),
    .data = icon_pixels
};
```

本例按小端 RGB565 内存表示编写，适合验证软件图像描述；不是屏幕链路字节顺序配置，也不保证每个硬件后端接受此小尺寸。

描述符和数据都保持长寿命，可通过 `lv_image_set_src()` 使用；不要在栈上临时创建后返回。

## 4. Flash、文件系统与解码

| 保存方式 | 优点 | 核对 |
| --- | --- | --- |
| 常量 C 资源 | 链接与部署简单 | 放置、访问、固件大小 |
| 外部 Flash 映射 | 大资源可独立组织 | XIP 竞争、硬件可达 |
| 文件资源 | 更新方便 | 路径、驱动、解码、错误 |

文件驱动应返回真实读取长度和错误。截断文件不能靠补零伪装成功；解码失败应可见。

文件路径不是 GPU 可直接寻址的像素地址。需要解码/映射到适合的缓冲区。

## 5. 缓存设计

缓存应包含容量上限、淘汰规则、失效和正在使用资源的引用。

如果图片文件更新，应避免命中旧缓存；若缓存仍被任务读取，也不能立即释放。

| 场景 | 建议 |
| --- | --- |
| 常驻小图标 | 固定或可控缓存 |
| 页面大图 | 分页生命周期与峰值预算 |
| 动态文件 | 更新版本与失效 |
| 连续动画 | 预转换、预解码或可行的分块 |

扩大缓存不总是提高性能，可能挤占帧缓冲和任务内存。

## 6. 中文字体的三个条件

中文显示需要：

1. 字符串正确编码，通常为 UTF-8。
2. 字体包含相应字形和度量。
3. 控件使用正确字体和布局。

内置 Latin 字体不自动包含中文，内置 CJK 子集也不等于所有字符覆盖。

需要收集页面固定文字、动态状态、单位、数字、标点及可能由通信送来的字符。动态范围过大时，设计缺字通知和替代策略，不静默显示空白。

## 7. 字体预算不能只看字符数

假设每个字形占完整 24 × 24、4 bpp：

| 数量 | 纯位图量 |
| --- | --- |
| 200 字形 | 57,600 B = 56.25 KiB |
| 5,000 字形 | 1,440,000 B = 1,406.25 KiB |

这是量级估算，实际还有度量、索引、kerning、压缩及不同字形大小。

用离线转换器裁剪已知字符集，记录工具版本、字号、bpp、许可和输出容量。

如果多种字号同时存在，要分别预算，不能以一套字库代表所有样式。

## 8. 字符串和对象生命周期

`lv_label_set_text()` 一类复制接口与 static 文本接口的寿命契约不同。使用 static 文本时，原数据必须持续有效并按规则触发更新。

不要在每次传感器更新时创建新标签或新字体。尽量复用对象，只更新真实变化内容。

切换页面时，清理 timer、回调和外部引用，再释放相应资源，避免后台仍访问已删除对象。

## 9. 验证与小结

检查透明边缘、各后端颜色、冷/热资源、缺文件、截断文件、缺字、切页峰值和多次切换后的释放。

资源“显示一次成功”不证明缓存和长时间生命周期正确。
